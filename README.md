## Project Overview

Determining the age of an abalone (a sea snail) traditionally means cutting its shell, staining it and counting the rings under a microscope. This project predicts the number of rings (age ≈ rings + 1.5 years) from easy-to-obtain physical measurements, and packages the model as a production-ready system:

- **Training pipeline** orchestrated with Prefect, with scheduled retraining
- **REST API** (FastAPI + Pydantic) serving predictions
- **Docker image** running the API and the Prefect server

Dataset: [Abalone dataset on Kaggle](https://www.kaggle.com/datasets/rodolfomendes/abalone-dataset).

## Getting Started

### Prerequisites

- [uv](https://docs.astral.sh/uv/getting-started/installation/) (it installs Python 3.11 for you if needed)
- [Docker](https://docs.docker.com/get-docker/) (on Windows/WSL: Docker Desktop with WSL integration enabled)
- A [Kaggle account](https://www.kaggle.com/account/login) to download the dataset

### 1. Set up the environment

```bash
# Install dependencies (creates .venv)
uv sync --all-groups

# Activate the virtual environment
source .venv/bin/activate  # on Windows: .venv\Scripts\activate

# Install pre-commit hooks (ruff linting/formatting before each commit)
pre-commit install
```

Pre-commit checks also run in CI on every push and pull request (see `.github/workflows/ci.yaml`).

### 2. Download the dataset

Download `abalone.csv` from [Kaggle](https://www.kaggle.com/datasets/rodolfomendes/abalone-dataset) and place it at `data/abalone.csv`.

### 3. Train the model

From the project root:

```bash
python -m src.modelling.main data/abalone.csv
```

This runs the Prefect training flow (load → clean → split → preprocess → train → evaluate → save) and writes `model.pkl` and `dict_vectorizer.pkl` to `src/web_service/local_objects/`. These objects are required by the API.

### 4. (Optional) Schedule retraining with Prefect

1. Point the CLI at your local Prefect server (Windows users may prefer `127.0.0.1` instead of `0.0.0.0`):

   ```bash
   prefect config set PREFECT_API_URL=http://0.0.0.0:4200/api
   ```

2. Start the Prefect server (leave this terminal open) and open the dashboard at [http://localhost:4200](http://localhost:4200):

   ```bash
   prefect server start --host 0.0.0.0
   ```

3. In **another terminal**, serve the retraining deployment (weekly, see `cron` in `deployment.py`):

   ```bash
   python -m src.modelling.deployment
   ```

4. In the UI, go to **Deployments** → **train-model** and use **Quick Run** to trigger a training immediately.

## Prediction API

The API exposes two endpoints:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/` | Health check |
| `POST` | `/predict` | Predict the number of rings and age of one abalone |

Inputs are validated with Pydantic: `sex` must be `M`, `F` or `I` and all measurements must be strictly positive (invalid inputs return a `422` error).

### Run with Docker (recommended)

Make sure you trained the model first (step 3): the pickled objects are copied into the image.

```bash
docker build -f Dockerfile.app -t abalone-api .
docker run -p 0.0.0.0:8000:8001 -p 0.0.0.0:4200:4201 abalone-api
```

- API documentation (interactive): [http://localhost:8000/docs](http://localhost:8000/docs)
- Prefect UI: [http://localhost:4200](http://localhost:4200)

### Run locally (without Docker)

From the project root, with the virtual environment active:

```bash
uvicorn src.web_service.main:app --reload
```

The API is then available at [http://localhost:8000/docs](http://localhost:8000/docs).

### Make a prediction

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "sex": "M",
        "length": 0.455,
        "diameter": 0.365,
        "height": 0.095,
        "whole_weight": 0.514,
        "shucked_weight": 0.2245,
        "viscera_weight": 0.101,
        "shell_weight": 0.15
      }'
```

Response:

```json
{"rings": 12.35, "age": 13.85}
```

You can also use the **Try it out** button on the `/docs` page.

## Development

### Managing dependencies

Add or update packages with uv, which updates `pyproject.toml` and `uv.lock`:

```bash
uv add <package>==<version>
```

The repo also keeps `requirements.in` / `requirements-dev.in` (pip-tools) in sync with `pyproject.toml`. After changing `.in` files, recompile them:

```bash
uv run --with pip-tools pip-compile requirements.in -o requirements.txt
uv run --with pip-tools pip-compile requirements-dev.in -o requirements-dev.txt
```

### Code quality

```bash
pre-commit run --all-files
```

This runs ruff (linting + formatting) and basic file checks; the same checks run in CI.
